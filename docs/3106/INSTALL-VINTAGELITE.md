## Восстановление применённых патчей

Ошибка «Another patch is active for these files» означает, что сохранённый
журнал другого патча всё ещё занимает те же файлы. По этому сообщению нельзя
судить о совместимости конкретной версии iOS. Перед заменой нужно вернуть
оригиналы прежнего патча.

Теперь из окна этой ошибки доступна кнопка Open applied patches. Общий список
Applied patches также открывается кнопкой восстановления слева во вкладке
Patches и из настроек Home. Он читает сохранённые журналы и не требует старого
пакета в каталоге. Старые записи без названия показываются как Previously
applied patch с приложением, датой и коротким ID. Прерванные применения также
доступны для восстановления.

Закройте целевое приложение, выберите прежнее применение и нажмите Restore.
Подтвердите возврат оригиналов и дождитесь сообщения об успехе. После этого
закройте список и примените NECK VINTAGE. Если игра уже изменила эти файлы,
появится отдельное подтверждение их замены сохранёнными оригиналами.
Запись деактивируется только после успешного восстановления. Журналы и
резервные копии сохраняются; защита от конфликтующих применений остаётся.

Устанавливайте обновление поверх существующего приложения с сохранением
его данных и прежним профилем подписи: в данных лежат оригиналы и журналы.
Не удаляйте приложение, журналы или резервные копии ради снятия блокировки.
В CI добавлен тест полного сценария: удалённый старый пакет, конфликт,
восстановление оригиналов и применение замены, а также старый журнал и
подтверждение изменённых игрой файлов. Компиляция и запуск Swift-теста
выполняются на macOS в GitHub Actions.

## Исправление доступа

Убрана добавленная ранее проверка полного sandbox-доступа для kernel-пути.
Исходный 3106 на iOS 17/18 допускает успешную инициализацию kernel R/W,
даже если этот дополнительный probe возвращает false. Фактические операции
с файлами и восстановлением по-прежнему проверяются транзакцией.
Во время инициализации Apply показывает подготовку и временно недоступен.
Home показывает статус доступа для всех поддерживаемых backend.

Это исправление не добавляет поддержку новых версий iOS и не выдаёт права
подписи. Для worse_query по-прежнему нужен действующий App Group из профиля.
Для проверки конкретного отказа нужны версия и build iOS, статус Home и лог
с пострадавшего телефона. Проверка на устройстве после сборки обязательна.

## Публикация из Windows

Получите release-2.2.8 из bundle в основном репозитории, затем создайте чистый
worktree из FETCH_HEAD и запустите tools/Publish-VintageLite-2.2.8.ps1 оттуда.
Скрипт устанавливает зависимости Worker, выполняет только идемпотентный SQL
0009 через wrangler d1 execute --remote --yes --file, разворачивает Worker с --keep-vars
и лишь после успеха отправляет main и v2.2.8 одной атомарной операцией.
Для Wrangler используется действующая авторизация Cloudflare этого компьютера.
Папка патчей, исходники и HEAD проверяются до обновления сервера и перед
отправкой коммита. Изменённый или добавленный локальный патч останавливает
публикацию, чтобы обновлённые файлы не остались вне выпуска.
При любой ошибке публикация останавливается. Старые reseller-миграции не
переигрываются. Локальная рабочая папка основного проекта сохраняется.
После развёртывания обновите страницу админки. Новая IPA появляется в Releases
после успешного выполнения VintageLite Full Release в GitHub Actions.

## Подпись

Сохранены bundle ID com.apple.mobile.MobileHouseArrest и Keychain-сервис
VintageLite.activation. Обновление должно сохранять подпись и доступ к Keychain,
чтобы использовать прежний сохранённый ключ. Требуемое App Groups entitlement
должно быть действительно разрешено профилем подписи.

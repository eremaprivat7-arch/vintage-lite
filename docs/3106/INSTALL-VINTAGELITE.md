# VintageLite 2.0.0 · build 9

Основа приложения — 3106 версии 3.2.3, commit bd7727ca7ab6b0477b83a3f2d3da6862db6d8d31.

## Что переносится

Основные экраны, разделы и системная совместимость берутся из 3106.
Экран входа, сохранение ключа, периодическая серверная проверка, режим патча
по версиям, аккаунт с таймером и ссылки Telegram перенесены из VintageLite.
Аккаунт открывается в Settings → «Аккаунт VintageLite» → «Ключ, срок и бонус».
Встроенные пакеты находятся в Features → Patch Projects.

Пакеты продолжают храниться в ThreeOneOSFive/Patches. Новый Xcode-проект
включает эту папку в IPA как ресурс Patches. Приложение читает форматы
.3105 и .3106. Перенесён имеющийся декодер V9 с проверкой допустимых функций.
Файлы пакетов сохраняются побайтово. Совпадающие ID пакетов обрабатываются
по принятому механизму одной записи на ID.

Обнаружены 37 пакетов с 33 различными ID. 36 файлов открылись с паролем
@osinxshop. SKIN DMITRI V5.3105 требует проверки собственного пароля
или исходной копии. Он остаётся в ресурсах. После открытия его карточки
можно ввести пароль. Содержимое пакета и пароль при этом не меняются.

## Лицензионный сервер

Приложение обращается к существующему
https://vintage-lite-license.vintage-lite-keys.workers.dev.

Миграционный патч не изменяет license-server, reseller-bot или таблицы D1.
Ключи, пароли админки, API-токены реселлеров, балансы и заказы продолжают
обслуживаться текущим сервером. Для этой миграции команды Wrangler не требуются.

Сохраняются bundle ID com.apple.mobile.MobileHouseArrest и Keychain-сервис
VintageLite.activation с аккаунтом license. При первом запуске нового приложения
текущий identifierForVendor сохраняется в отдельную запись device-id и
используется при последующих проверках.

## Сборка

1. Примените патч и отправьте изменения через приложенный Windows-скрипт.
2. В GitHub Actions откройте Build VintageLite 3106 IPA.
3. Дождитесь прохождения проверок и сборки.
4. Скачайте Artifacts → VintageLite-3106-unsigned.
5. Распакуйте VintageLite-3106-unsigned.ipa.

Перед сборкой выполняются проверки конфигурации VintageLite,
политик и локализаций 3106, а также совместимости пакетов.
Проверка формата с известным неправильным паролем выводит PASSWORD REQUIRED.

## Подпись и обновление iPhone

Для работы 3106 на iOS 27 требуется действующее App Groups entitlement.
Этот capability должен присутствовать в профиле, которым подписывается IPA.

README исходного 3106 рекомендует Impactor или Xcode и отдельно предупреждает,
что Sideloadly удаляет App Groups при подписи. В ESign нужен сертификат и профиль
с явным App ID и разрешённой группой. Обычный wildcard-профиль App Groups
не предоставляет. Способ подписи должен сохранить действующее entitlement
com.apple.security.application-groups, разрешённое профилем. Одного изменения
строки в entitlements недостаточно: группа должна быть действительно выдана
при подписи. Конкретный профиль ещё нужно проверить на вашем iPhone.

Установите обновление поверх текущего VintageLite, сохранив bundle ID.
Сохранение прежней команды подписи и доступа к Keychain важно для переноса
сохранённого ключа. До подтверждения обновления оставьте текущую IPA и
сертификат доступными для восстановления.

При изменении bundle ID или команды подписи iOS может выдать другой
identifierForVendor и другой доступ к Keychain. База ключей на сервере
при этом сохраняется. Если старый ключ сообщает о занятом месте,
владелец может открыть его в админке, отключить старую привязку устройства
и дать клиенту активировать тот же ключ заново. Это ручное действие
сохраняет срок ключа и выполняется после проверки клиента.

## Режим патча

В админке «Патч по версиям приложения» добавьте версию 2.0.0, сборку 9
со входом «Открыт». По текущей политике незарегистрированные версии
также проходят обычную проверку ключа.

Сначала проверьте новую IPA на своём телефоне и опубликуйте её клиентам.
После этого можно закрыть 1.2.0 · 8 и строку старых сборок без номера.
Завершение общего патча сохраняет запреты конкретных версий.

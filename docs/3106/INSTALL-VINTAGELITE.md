# VintageLite 2.2.10 · build 21

## Исправление проверки сборки

В тесте восстановления сравниваются ID транзакции, ID проекта и канонический
путь к журналу. Это учитывает разные представления URL одного файла на macOS.
Дальнейшие проверки восстанавливают оригиналы через найденный журнал, как
это делает экран Applied patches.

Ветки ci/** выполняют полную сборку и проверки без публикации. Тег v2.2.10
публикует IPA только после успешных проверок. Имя тега сверяется с версией
приложения.

## Контакты и бот

Из «Аккаунта» убраны строки покупки ключа и канала под бонусом.
Кнопка «Получить бонус» по-прежнему открывает @vintagelite_bot.
В Home → Настройки → Социальные сети оставлен только @VintageLiteStatus.
На этот же канал ведёт кнопка обязательного обновления. Контакт @osinxff
в ошибках защищённой загрузки сохранён.

Telegram-бот больше не показывает прайс, суммы покупок в статистике и кнопку
покупки. Прежние команды покупки/цен и кнопки buy: не создают заказы.
При нажатии старой кнопки бот заменяет старый прайс нейтральным сообщением.
Бонусы, проверка срока, личные ключи и баланс продолжают работать. Внешний
авторизованный Reseller API сохраняет возможность покупки.
После публикации отправьте /start боту для обновления клавиатуры.
Ранее отправленные прайсы в истории чата нужно удалить отдельно: полная
история сообщений не хранится в базе бота.

Встроенный набор совпадает с загрузкой patch-files-clean-b1344e26e613:
22 ModSkin и один FPSBoost/NECK VINTAGE.3105. FPS и Holo пустые.
NECK VINTAGE открывается паролем приложения; SKIN DMITRI V5 требует своего пароля.
Серверный каталог патчей отключён для этой сборки.

## Восстановление применённых патчей

Ошибка «Another patch is active for these files» означает, что сохранённый
журнал другого патча всё ещё занимает те же файлы. По этому сообщению нельзя
судить о совместимости конкретной версии iOS. Перед заменой нужно вернуть
оригиналы прежнего патча.

Теперь из окна этой ошибки доступна кнопка Open applied patches. Общий список
Applied patches также открывается кнопкой восстановления слева во вкладке
Patches и из настроек Home. Он читает сохранённые журналы и не требует старого
пакета в каталоге. Старые записи без названия показываются как Previously
applied patch с приложением, датой и коротким ID. Прерванные применения также
доступны для восстановления.

Закройте целевое приложение, выберите прежнее применение и нажмите Restore.
Подтвердите возврат оригиналов и дождитесь сообщения об успехе. После этого
закройте список и примените NECK VINTAGE. Если игра уже изменила эти файлы,
появится отдельное подтверждение их замены сохранёнными оригиналами.
Запись деактивируется только после успешного восстановления. Журналы и
резервные копии сохраняются; защита от конфликтующих применений остаётся.

Устанавливайте обновление поверх существующего приложения с сохранением
его данных и прежним профилем подписи: в данных лежат оригиналы и журналы.
Не удаляйте приложение, журналы или резервные копии ради снятия блокировки.
В CI добавлен тест полного сценария: удалённый старый пакет, конфликт,
восстановление оригиналов и применение замены, а также старый журнал и
подтверждение изменённых игрой файлов. Компиляция и запуск Swift-теста
выполняются на macOS в GitHub Actions.

## Исправление доступа

Убрана добавленная ранее проверка полного sandbox-доступа для kernel-пути.
Исходный 3106 на iOS 17/18 допускает успешную инициализацию kernel R/W,
даже если этот дополнительный probe возвращает false. Фактические операции
с файлами и восстановлением по-прежнему проверяются транзакцией.
Во время инициализации Apply показывает подготовку и временно недоступен.
Home показывает статус доступа для всех поддерживаемых backend.

Это исправление не добавляет поддержку новых версий iOS и не выдаёт права
подписи. Для worse_query по-прежнему нужен действующий App Group из профиля.
Для проверки конкретного отказа нужны версия и build iOS, статус Home и лог
с пострадавшего телефона. Проверка на устройстве после сборки обязательна.

## Сервер и список версий

В серверном обновлении 2.2.9 миграция 0010 создаёт только таблицу app_releases при её отсутствии и добавляет
2.2.4/15, 2.2.5/16, 2.2.6/17, 2.2.7/18, 2.2.8/19 и 2.2.9/20 через INSERT OR IGNORE. Существующие запреты,
ключи, HWID, сроки и балансы не меняются. Другие версии регистрируются после
успешной проверки ключа; неверные ключи не добавляют строки.
Панель сортирует версии численно и содержит кнопку «Обновить список».

## Публикация из Windows

Сервер и бот используют уже выполненное обновление 2.2.9. Для этого исправления
их повторное развёртывание и миграции не нужны. Версия 2.2.10/21 добавляется
в список версий при успешной проверке действующего ключа; затем обновите
список в админке.

Получите release-2.2.10 из bundle в основном репозитории, создайте чистый
worktree из FETCH_HEAD и запустите tools/Publish-VintageLite-2.2.10.ps1 оттуда.
Скрипт отправляет отдельную ветку ci/**, ожидает успешную полную сборку
конкретного коммита и только после успеха атомарно отправляет main и v2.2.10.
При ошибке или невозможности проверить CI публикация останавливается.
Скрипт не выполняет миграции и не разворачивает Worker повторно.
Новая IPA появляется в Releases после успешного выполнения VintageLite Full
Release для тега. Скрипт Publish-VintageLite-2.2.9.ps1 предназначен для
предыдущего выпуска и не используется для этого исправления.

## Подпись

Сохранены bundle ID com.apple.mobile.MobileHouseArrest и Keychain-сервис
VintageLite.activation. Обновление должно сохранять подпись и доступ к Keychain,
чтобы использовать прежний сохранённый ключ. Требуемое App Groups entitlement
должно быть действительно разрешено профилем подписи.

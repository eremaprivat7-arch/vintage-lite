## Исправление доступа

Убрана добавленная ранее проверка полного sandbox-доступа для kernel-пути.
Исходный 3106 на iOS 17/18 допускает успешную инициализацию kernel R/W,
даже если этот дополнительный probe возвращает false. Фактические операции
с файлами и восстановлением по-прежнему проверяются транзакцией.
Во время инициализации Apply показывает подготовку и временно недоступен.
Home показывает статус доступа для всех поддерживаемых backend.

Это исправление не добавляет поддержку новых версий iOS и не выдаёт права
подписи. Для worse_query по-прежнему нужен действующий App Group из профиля.
Для проверки конкретного отказа нужны версия и build iOS, статус Home и лог
с пострадавшего телефона. Проверка на устройстве после сборки обязательна.

## Сервер и список версий

Миграция 0007 создаёт только таблицу app_releases при её отсутствии и добавляет
2.2.4/15, 2.2.5/16 и 2.2.6/17 через INSERT OR IGNORE. Существующие запреты,
ключи, HWID, сроки и балансы не меняются. Другие версии регистрируются после
успешной проверки ключа; неверные ключи не добавляют строки.
Панель сортирует версии численно и содержит кнопку «Обновить список».

## Публикация из Windows

Получите release-2.2.6 из bundle в основном репозитории, затем создайте чистый
worktree из FETCH_HEAD и запустите tools/Publish-VintageLite-2.2.6.ps1 оттуда.
Скрипт устанавливает зависимости Worker, выполняет только идемпотентный SQL
0007 через wrangler d1 execute --remote --file, разворачивает Worker с --keep-vars
и лишь после успеха отправляет main и v2.2.6 одной атомарной операцией.
Для Wrangler используется действующая авторизация Cloudflare этого компьютера.
При любой ошибке публикация останавливается. Старые reseller-миграции не
переигрываются. Локальная рабочая папка основного проекта сохраняется.
После развёртывания обновите страницу админки. Новая IPA появляется в Releases
после успешного выполнения VintageLite Full Release в GitHub Actions.

## Подпись

Сохранены bundle ID com.apple.mobile.MobileHouseArrest и Keychain-сервис
VintageLite.activation. Обновление должно сохранять подпись и доступ к Keychain,
чтобы использовать прежний сохранённый ключ. Требуемое App Groups entitlement
должно быть действительно разрешено профилем подписи.

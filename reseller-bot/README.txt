Vintage Lite · Telegram reseller
Распакуй архив и открой PowerShell в этой папке. Нужны Node.js, Python и доступ к тому же аккаунту Cloudflare, что и у vintage-lite-license. База должна содержать миграции 0001, 0002 и 0003 действующего сервера, включая reseller_access. Для этой версии также нужна license-server/migrations/0011_bot_only_resellers.sql (отдельный список bot_resellers). Проверь название и ID D1 в wrangler.jsonc.

npx wrangler login
npx wrangler d1 execute vintage-lite-keys --remote --file=./schema.sql
npx wrangler d1 execute vintage-lite-keys --remote --file=../license-server/migrations/0011_bot_only_resellers.sql
npx wrangler deploy
npx wrangler secret put TELEGRAM_BOT_TOKEN
npx wrangler secret put ADMIN_ID
npx wrangler secret put WEBHOOK_SECRET
npx wrangler secret put KEY_SECRET

Введи значения по запросу: токен BotFather, свой числовой Telegram ID, случайный webhook-секрет (буквы и цифры, 32–64 символа) и отдельный случайный секрет для ключей. Сохрани KEY_SECRET: он позволяет повторно показать выданные ключи. Для внешнего клиента API отдельно установи токен командой npx wrangler secret put API_TOKEN.

py webhook.py

Введи токен, тот же WEBHOOK_SECRET и URL нового Worker из вывода deploy. Telegram переключит доставку событий этого бота на новый webhook.

Для обновления уже настроенного проекта используй tools/Update-VintageLite-BotAccess.ps1 из чистого worktree обновления. Скрипт проверяет репозиторий и актуальность main, запускает тесты бота и сервера, создаёт только таблицу bot_resellers, затем разворачивает vintage-lite-license (админку) и vintage-lite-reseller (бота). Существующие API-токены, индивидуальные цены, балансы, ключи и профили сохраняются. Скрипт не повторяет schema.sql или прежние миграции, не меняет ADMIN_ID, токен бота, KEY_SECRET и webhook. Затем отправляет проверенный коммит в main без тега новой IPA. Прежний Update-VintageLite-ResellerBot.ps1 вызывает этот же сценарий. Команды выше предназначены только для первоначальной настройки нового Worker.

Как добавить реселлера только в своего бота:
1. Открой https://vintage-lite-license.vintage-lite-keys.workers.dev/admin и войди своим паролем.
2. В блоке «Реселлеры Telegram-бота» введи числовой Telegram ID и нажми «Добавить реселлера». Имя, API-токен и цены не нужны.
3. Пополни его баланс через меню владельца бота или /balance 123456789 +1000.
4. Реселлер пишет /start в @vintagelite_bot и получает кнопку «🔑 Получить ключ».

Бот проверяет отдельную таблицу bot_resellers. Новый список изначально пуст: добавь нужные Telegram ID через форму. Наличие API-токена, баланса или бонуса само по себе не разрешает покупать через Telegram. Владелец ADMIN_ID сохраняет доступ без добавления в этот список.

«Убрать из бота» отключает только новые покупки через Telegram, включая старые кнопки. История ключей, баланс и API остаются. Бонус и проверка срока доступны всем. Права повторно проверяются в SQL создания заказа, чтобы отзыв доступа во время обработки не привёл к списанию.

Блок «Реселлеры API / настройки» работает как раньше: создание/показ/перевыпуск токена, индивидуальные цены, отключение API, кабинет и история. API-реселлера можно отдельно добавить в бот по тому же Telegram ID. Отключение/удаление/перевыпуск API не меняет доступ в бот; добавление/удаление из бота не меняет API. Для одного Telegram ID кошелёк общий.

Единый прайс Telegram: 1 день — 250 ₸; 3 дня — 700 ₸; 7 дней — 1500 ₸; 15 дней — 3500 ₸; 30 дней — 5000 ₸. Он применяется к владельцу и допущенным реселлерам. Эти цены заданы для Telegram; индивидуальные цены Reseller API и прежние тарифы внешнего API не переписываются. Бонусы, их суммы и настройки базы сохраняются.

Покупатель выбирает срок и цену. Ключ выдаётся отдельной HTML-карточкой: бренд, ключ, срок, статус и кнопка «Скопировать ключ». Строки «Списано» и суммы покупки в карточке нет. Установленная цена списывается с кошелька самого покупателя; повторное нажатие в том же сообщении возвращает тот же ключ без повторного списания. Для нового заказа снова открой «🔑 Получить ключ». Подмена цены, недостаточный баланс или отсутствие допуска не создают ключ. Повтор уже оплаченного старого заказа сохраняет его первоначальную цену и ключ.

Суммы покупок в статистике не выводятся. /balance 123456789 +5000 пополняет кошелёк, /balance 123456789 -1000 списывает только для ADMIN_ID; добавление реселлера не выдаёт ему права администратора. ID пользователь увидит в «Мой баланс». Внешний авторизованный API покупки использует прежний контракт. Ранее отправленные прайсы в истории чата не удаляются автоматически.

У каждого личного ключа один бонус. Первый, кто вводит ключ в личном чате, получает деньги на свой баланс, срок продлевается у владельца ключа. Работает и для ключей сайта соответствующих сроков. Общие, отозванные и просроченные ключи не участвуют. У неактивированного ключа срок начнётся при активации.

API: POST /api/purchase, Authorization: Bearer <API_TOKEN>, Content-Type: application/json
Тело: {"uid":"123456789","order_id":"order-123","days":7,"price":1500}
Возвращает key, days, cost. При повторной попытке после обрыва связи отправь тот же order_id и параметры.

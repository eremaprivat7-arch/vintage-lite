Vintage Lite · Telegram reseller
Распакуй архив и открой PowerShell в этой папке. Нужны Node.js, Python и доступ к тому же аккаунту Cloudflare, что и у vintage-lite-license. База должна содержать миграции 0001 и 0002 действующего сервера. Проверь название и ID D1 в wrangler.jsonc.

npx wrangler login
npx wrangler d1 execute vintage-lite-keys --remote --file=./schema.sql
npx wrangler deploy
npx wrangler secret put TELEGRAM_BOT_TOKEN
npx wrangler secret put ADMIN_ID
npx wrangler secret put WEBHOOK_SECRET
npx wrangler secret put KEY_SECRET

Введи значения по запросу: токен BotFather, свой числовой Telegram ID, случайный webhook-секрет (буквы и цифры, 32–64 символа) и отдельный случайный секрет для ключей. Сохрани KEY_SECRET: он позволяет повторно показать выданные ключи. Для внешнего клиента API отдельно установи токен командой npx wrangler secret put API_TOKEN.

py webhook.py

Введи токен, тот же WEBHOOK_SECRET и URL нового Worker из вывода deploy. Telegram переключит доставку событий этого бота на новый webhook.

Для обновления уже настроенного бота используй tools/Update-VintageLite-OwnerBot.ps1 из чистого worktree обновления. Скрипт проверяет основной репозиторий, запускает тесты бота и разворачивает только vintage-lite-reseller с сохранением секретов. Он не запускает schema.sql и не меняет ADMIN_ID, токен бота, KEY_SECRET или webhook. Затем отправляет проверенный коммит в main без тега новой IPA. Команды выше предназначены только для первоначальной настройки нового Worker.

Открой личный чат с ботом и отправь /start. Только пользователь с числовым Telegram ID из существующего ADMIN_ID увидит «🔑 Получить ключ» и тарифы. Проверка владельца выполняется и при команде, и при каждом нажатии кнопки buy:. Без ADMIN_ID покупка закрыта. Для остальных пользователей покупка и прайс скрыты, в том числе через старые кнопки. Бонус, проверка срока, «Мои ключи» и баланс доступны.

Владелец выбирает срок и цену. Ключ выдаётся отдельной HTML-карточкой: бренд, ключ, срок, статус и кнопка «Скопировать ключ». Строки «Списано» и суммы покупки в карточке нет. Покупка по-прежнему списывает установленную цену с кошелька владельца; повторное нажатие в том же сообщении возвращает тот же ключ без повторного списания. Для нового заказа снова открой «🔑 Получить ключ». Неверная цена или недостаточный баланс не создают ключ.

Суммы покупок в статистике не выводятся. /balance 123456789 +5000 пополняет кошелёк, /balance 123456789 -1000 списывает для администратора. ID пользователь увидит в «Мой баланс». Внешний авторизованный API покупки использует прежний контракт. Ранее отправленные прайсы в истории чата не удаляются автоматически.

У каждого личного ключа один бонус. Первый, кто вводит ключ в личном чате, получает деньги на свой баланс, срок продлевается у владельца ключа. Работает и для ключей сайта соответствующих сроков. Общие, отозванные и просроченные ключи не участвуют. У неактивированного ключа срок начнётся при активации.

API: POST /api/purchase, Authorization: Bearer <API_TOKEN>, Content-Type: application/json
Тело: {"uid":"123456789","order_id":"order-123","days":7,"price":1500}
Возвращает key, days, cost. При повторной попытке после обрыва связи отправь тот же order_id и параметры.
